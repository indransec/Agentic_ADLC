The framework

Ten terminals, each answering one question before the agent may move on

T0

Intake

Should we do this at all?

T1

Requirements

What must the agent achieve?

T2

Design

How should it operate?

T3

Build

Can we build it reproducibly?

T4

Evaluation

Does it behave as designed?

T5

Assurance

Is it safe and compliant?

T6

Readiness

Is production ready for it?

T7

Deployment

Can it go live safely?

T8

Operations

Is it working as expected?

T9

Evolve / Retire

Improve it, or retire it?

Each terminal is a versioned spec, not code

Every run ends in a person’s decision

Every decision lands in the ledger

The ten questions come straight from the terminal specs’ purpose lines. Specs live as YAML in adlc-specs and are versioned and pinned per run, so changing the process never needs a code change. Engineers: the spec defines prerequisites, actors, authorities, playbooks, controls, evidence, outcomes and the timeline.
