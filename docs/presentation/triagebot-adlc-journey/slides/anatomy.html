Under the hood

Five parts of the platform take part in every run

Orchestrator

events · states

Opens a run when an event arrives, moves it through its states, routes the outcome to the next terminal.

Terminal agent

model · MCP tools

Gets a context pack: spec, profile, earlier evidence, playbooks. Calls only the tools its authorities allow.

Policy engine

controls · authorization

Checks prerequisites and controls from the spec, every tool call, and the run’s data ceiling.

Reviewer agent

checklist · recommend

An independent agent scores the checklist and recommends an outcome. It never decides.

People

inbox · board

Answer questions, edit artifacts, approve, and choose the outcome. Their decision closes the run.

Ledger sealed

Everything that happens is appended to the ledger and tied to the spec version, the actor and a content hash. Nothing can be edited or deleted afterwards.

Engineering slide. The orchestrator is a state machine on the database (ADR-01). Agents reach enterprise systems only through MCP servers, and authorization is deny by default. Controls are CEL rules written in the spec; a failed control sends the agent back to work, up to the spec’s retry cap (3 by default), then the run escalates. People can edit an artifact at sign-off or escalated; the edit is a new version and the controls run again before anyone decides. Ledger rows are append-only: database triggers refuse UPDATE and DELETE, and adlc-ledger verify detects any bypass. Tracing links every step by run id.
